- (decision) Working mode: Coaching path
- (decision) Deliverable: Architecture spine only (build substrate)
- (decision) AD-1 (Persistence): Use sqlite-jdbc with Quarkus Agroal DataSource and Flyway schema migrations, using explicit Kotlin Repository/DAO
- (decision) AD-2 (Frontend & Packaging): Modern Vanilla TypeScript/JavaScript with Vite for UI and Leaflet, built and served via Quarkus META-INF/resources in a multi-stage Dockerfile
- (decision) AD-3 (Build Tool & Runtime): Gradle with Kotlin DSL (build.gradle.kts) in JVM mode on Java 21 for reliable sqlite-jdbc JNI support
- (decision) AD-4 (API Contract & Model): REST API uses nested location object (latitude, longitude) for future bearing expansion, UUIDv7 string IDs, and ISO-8601 UTC timestamps
- (decision) AD-5 (Data Schema & Time): SQLite sightings table stores id, user_id, user_name, latitude, longitude, recorded_at, created_at. Bearing omitted until feature implemented. Timestamps stored strictly in UTC, displayed on frontend in browser local time.
- (decision) AD-6 (Frontend Architecture & UI Invariants): Client user_id and user_name in localStorage; background watchPosition keeps GPS coordinates hot; 3-5s tap cooldown; tab navigation for Track/Map/List; Leaflet OSM map with distinct marker coloring for matching user_id and toggle to filter out other users
- (event) spine finalized
- (decision) API Versioning: URI path versioning with /api/v1 prefix adopted
- (decision) API Collection Envelope: GET /api/v1/sightings wraps results in { items, total } object with limit and offset query parameters
- (decision) Backlog: Geospatial viewport bounding-box query (bbox parameter) deferred to backlog
- (decision) Backlog: Batch upload endpoint (POST /api/v1/sightings/batch) for offline sync deferred to backlog
- (decision) Backlog Hint: Shoe metadata attributes (type/color) should be modeled as an extensible attributes JSON container
- (decision) Identity for MVP: user_id and user_name are the same string (the user's entered name). Dedicated login with profile and changeable username deferred to backlog.
- (decision) AD-4 (API User Identity Pattern): POST uses flat user_id ({ user_id, location, recorded_at }), whereas GET / responses return an embedded user object ({ id, user: { id }, location, recorded_at, created_at }). user_id is used everywhere across wire and database.
- (decision) Real-Time Streaming: Server-Sent Events (SSE) and in-process EDA for live map marker updates deferred to backlog; MVP uses standard REST queries.
- (decision) Runtime Target: Upgraded Java LTS target from 21 to 25
- (decision) AD-5 & AD-1 Hardening: Move SQLite PRAGMAs out of Flyway DDL to Agroal DataSource init-sql; enforce write serialization lock in SightingRepository; use Foojay toolchains plugin for Java 25.
